PRÁCTICA N2 - GIT, GITHUB Y HTML
  1. ¿Qué es una rama (branch) en Git y para qué sirve?

    2. Una rama (branch) en Git es un puntero móvil y ligero hacia una confirmación (commit) específica, que permite crear una línea de desarrollo independiente y aislada del código principal. Sirve para experimentar, añadir nuevas funcionalidades o corregir errores sin afectar la estabilidad del proyecto principal (main o master)

  2. ¿Cómo se crea y se cambia entre ramas en Git?

    3. Para crear y cambiar entre ramas en Git, usa git checkout -b seguido de git checkout para hacerlo por separado. Las ramas permiten trabajar en paralelo, facilitando funciones nuevas o correcciones sin afectar la rama principal (master/main).

  3. ¿Cuál es la diferencia entre la rama main y otras ramas?

    4. La rama main es la parte principal del proyecto, donde está el trabajo final y correcto. Es como la versión “oficial”. Las otras ramas son copias que se usan para trabajar sin arruinar lo principal. Ahí puedes probar cosas, hacer cambios o arreglar errores. Cuando todo está bien, esos cambios se pasan a la rama main.

  4. ¿Cómo se combinan ramas en Git (merge)?

    5. Para combinar ramas en Git usando el comando merge, el proceso se basa en un concepto clave: te posicionas en la rama que recibirá los cambios y desde ahí "llamas" a la rama que quieres integrar.

  5. ¿Qué problemas pueden ocurrir al trabajar con ramas (conflictos) y cómo se resuelven?

    6. Pasa cuando dos ramas modifican la misma parte de un archivo.
    Git no sabe cuál cambio elegir.
    Rama A cambia una línea. Rama B cambia esa misma línea.
    COMO SE RESUELVE
    Eliges qué código dejar o combinas ambos Borras los símbolos (<<<<<<<, =======, >>>>>>>)
    Despues marcar como resuelto git add archivo.txt
    Despues termiar el merge git commit
